# Bartu Finance Holding — Business Context

## 1. Company Overview

Bartu Finance Holding (BFH) is a fictional multinational financial institution operating across Germany, the Netherlands, Poland, and Türkiye.

The organization employs approximately 35,000 people and operates a hybrid identity infrastructure consisting of five on-premises Active Directory domains and a target Microsoft Entra ID environment.

## 2. Business Challenges

The organization faces several identity management and security challenges:

- Manual and inconsistent identity lifecycle processes
- Fragmented identity management across multiple AD domains
- Delayed provisioning and deprovisioning
- Excessive and persistent privileged access
- Limited visibility into application permissions
- Inconsistent authentication and access policies
- Insufficient access governance and audit evidence

## 3. Project Objectives

The project aims to design and validate an enterprise identity solution that:

- Automates Joiner-Mover-Leaver (JML) processes
- Integrates on-premises identities with Microsoft Entra ID
- Enforces Zero Trust access controls
- Implements privileged access management
- Establishes identity governance and access certification
- Secures enterprise application integrations
- Uses Microsoft Graph and PowerShell for identity automation
- Supports monitoring, auditing, and incident response

## 4. Identity Sources and Target Systems

**Identity Sources**
- Human Resources system
- External contractor and partner records

**Identity Infrastructure**
- On-premises Active Directory
- Microsoft Entra ID
- IAM provisioning and orchestration components

**Target Resources**
- Microsoft 365
- Enterprise SaaS applications
- Internal business applications
- Privileged administration roles

## 5. Implementation Strategy

The project follows a scenario-based approach.

Each scenario includes business requirements, solution design, implementation steps, security considerations, test cases, and documented results.

## 6. Lab Scope

The lab will use a limited number of synthetic test identities to validate the proposed enterprise identity architecture.

The 35,000-user environment represents an enterprise-scale design scenario, not an actual deployed production environment.

Features requiring additional licensing or infrastructure will be identified before implementation.
